Jenkins 대기 시간을 약 25초 수준으로 줄이기 위해 Claude Code 스킬을 만든 기록

작성일 2026-05-26 In 인프라

대상 독자: AWS Lambda와 Step Functions를 직접 배포하는 개발자, 그리고 Claude Code를 실무에 붙여보려는 DevOps/인프라 담당자.
전제 조건: AWS CLI 설정 및 Claude Code CLI 설치 완료.

문제는 단순한 빌드 duration이 아니었다. Lambda 1개만 수정해도, 개발자가 체감하는 Jenkins 대기 시간은 생각보다 길었다.

Lambda 1개 수정 케이스에서 Jenkins는 Hook 수신부터 배포 완료까지 실측 67초였다. 평균 체감 시간으로 보면 약 2분 44초 수준이었다.

aws-deploy 스킬로 바꾼 뒤 같은 케이스에서 변경 감지 → 분석 보고 완료까지는 4.57초가 나왔다. 실제 배포를 끝내기 전, Stage 1 분석부터 Lambda 코드 zip·업로드까지 포함한 체감 총시간은 약 25초 [추정]로 보는 편이 더 보수적이다.

숫자를 바로 한 줄로 묶어 비교하면 오해가 생긴다. 4.57초는 Stage 1 분석 시간 실측값이고, 실사용 체감으로 비교하면 67초 vs 약 25초 [추정]에 더 가깝다.

이 숫자 차이가 이 글의 포인트는 아니다. 더 중요한 건 Jenkins 파이프라인에 없던 Step Functions definition 교체와 SF version·alias 핀닝이 이 스킬에는 들어 있다는 점이다. 속도를 줄인 것보다, 배포가 완결되는 기준 자체를 다시 정의했다는 쪽이 더 정확하다.
